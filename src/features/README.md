# 기능 디렉터리 작성법

`features/` 아래에는 플레이어가 경험하는 기능을 둡니다. 각 기능은 담당자 한 명이 클라이언트부터 서버 로직과 테스트까지 수직으로 책임집니다.
현재 스토리 챕터는 `chapter1/`, `chapter2/`, `chapter3/`로 구분합니다. 기존 리듬 호러 기능은 `chapter1/`, 기억 재구성 기능은 `chapter3/`에 있습니다.

```text
features/inventory/
├── client/                 # UI, 입력, 클라이언트 상태
├── server/                 # API, 검증, 저장 로직
├── shared/                 # 이 기능의 요청/응답 타입과 공통 규칙
├── assets/                 # 이 기능(챕터)에서만 사용하는 이미지·음원 등
└── tests/                  # 테스트, fixture, mock, 재현 시나리오
    └── inventory.test.ts
```

위 폴더를 처음부터 전부 만들지는 않습니다. 기능의 첫 파일은 기능 루트에 두고, 파일이 늘어 구분이 필요할 때 하위 폴더를 만듭니다. `welcome/`은 현재 클라이언트 코드만 필요하므로 `client/`만 존재합니다.

## 공통 코드로 옮기는 기준

- 최초 구현은 해당 기능 안에 둡니다.
- 비슷한 코드가 생기면 이름만 같지 않고 변경 이유도 같은지 비교합니다.
- 반복이 확실해졌을 때 `shared/` 또는 `platform/`으로 옮깁니다.
- 인증, 권한, 입력 검증, 오류 형식처럼 안전에 직접 영향을 주는 규칙은 처음부터 공통 기반으로 관리합니다.

기능 내부 `shared/`는 해당 기능의 클라이언트와 서버가 공유합니다. 최상위 `src/shared/`는 여러 기능에서 실제로 사용되는 작은 코드만 둡니다.

## 에셋 배치 기준

- 특정 챕터에서만 쓰는 에셋은 `src/features/chapterN/assets/`에 둡니다.
- 두 개 이상의 챕터가 공통으로 쓰는 에셋만 `src/assets/`에 둡니다.
- 에셋을 추가할 때는 사용 범위가 바뀌지 않는 한 챕터 폴더에서 관리합니다.
